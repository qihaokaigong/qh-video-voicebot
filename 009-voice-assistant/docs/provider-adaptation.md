# Provider 适配指南

当用户的实时语音接口和默认豆包 Seeduplex 不同时，最小摩擦的做法不是让用户手动重写整套固件，
而是让 Agent 在固定边界内完成一次可审查的适配。

## 适配前必须提供的公开信息

只提供官方、版本化文档或不含密钥的协议样例：

- WebSocket 或 HTTP 端点及 TLS 要求；
- 鉴权 Header 的字段名和作用，不提供真实值；
- 会话创建、开始输入、提交输入、取消和结束事件；
- 上行音频格式、采样率、位深、声道、帧长与编码；
- 下行文本、音频、完成和错误事件；
- 下行音频格式及最大单帧大小；
- 模型、音色、提示词和区域参数；
- 限流、超时、重连、计费和数据处理说明。

如果文档缺失关键字段，Agent 应先列为待确认项，不应根据相似接口猜测。

## 允许修改的范围

通常只应修改 `qh-voice-kit` 中：

- Provider 协议编码与事件解析；
- Provider 网络传输适配；
- 必要的配置 Schema、Wire 和本地配置页字段；
- 对应的无密钥协议夹具、单元测试和协议来源记录。

按钮、屏幕状态机、录音采集、缓冲播放、安全烧录和 QH 结构化同步应保持独立。除非产品基线明确
改变，不增加本地或云端 Voice Gateway，也不把 API Key 交给 QH 平台。

## Agent 应执行的顺序

1. 阅读默认实现和新 Provider 的官方文档；
2. 输出协议差异表、未知项、最小文件集合和回退方式；
3. 先为新协议帧、事件和错误写失败测试；
4. 实现适配并通过主机测试；
5. 使用目标硬件 Profile 完成干净固件编译；
6. 创建 `candidate`，不得直接标记为 `allowed`；
7. 展示 Release ID、Profile ID、串口和 Flash 计划，等待精确确认；
8. 实机验证屏幕、采音、文字、完整回答音频、断线恢复与重启；
9. 保存不含密钥和原始用户音频的验收证据，再决定是否晋升正式 Release。

可直接复制的讨论提示词见[接入指南中的“用户接口与当前实现不同怎么办”](../README.md#用户接口与当前实现不同怎么办)。

## 适配完成的最低验收

- 任何密钥都没有进入 Git、Agent 对话、命令行参数或 QH；
- 连接和事件解析测试覆盖正常、服务端错误、超时和超大帧；
- 上下行采样率和帧边界与官方文档一致；
- 屏幕能够区分连接、录音、等待、播放和错误；
- 回答音频连续，播放完成事件不会抢先截断尾部缓冲；
- 断电重启不需要电脑端常驻程序；
- Release Manifest 和固件哈希重新生成并验证。
